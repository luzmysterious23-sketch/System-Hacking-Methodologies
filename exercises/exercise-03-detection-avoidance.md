# Exercise 3 — Detection Avoidance

## Overview

This exercise examines the cleanup phase described in the System Hacking Methodologies lab: PowerShell history, the installed OpenStego application, local event logs, and Pablo's temporary privileged group membership.

**Environment:** Authorized Practice Labs training environment  
**Documentation basis:** Supplied lab instructions. The linked reference images have not been independently inspected, and execution-result screenshots for this exercise have not been supplied.

## Task 1 — Delete PowerShell History

### Objective

Understand the distinction between command history held in a PowerShell session and history persisted by PSReadLine.

### Lab Activity

The supplied procedure clears the session history, identifies the PSReadLine history-file location, and edits the saved history file in Pablo's profile. The activity demonstrates that these are separate history stores.

### Interpretation

Clearing session history alone does not clear the PSReadLine file. Conversely, editing the file is not proof that every record of PowerShell activity has been removed. Session state, configured logging, and records elsewhere must be distinguished from the history file itself.

The portfolio therefore records this as a history-management demonstration, not proof of complete evidence removal.

### Suggested Evidence Labels

- **PowerShell Session History Cleared**
- **PSReadLine History Location Identified**
- **Saved History File Reviewed After Cleanup**

## Task 2 — Remove the Installed Tool

### Objective

Remove the application introduced during the lab and its downloaded installer.

### Lab Activity

The procedure uninstalls OpenStego v0.8.4 through Windows Apps & features, removes its desktop installer, and empties the Recycle Bin.

### Interpretation

Application removal and file deletion are distinct cleanup actions. Neither demonstrates that installation records, file-system artifacts, or other traces are absent. The lab's suggestion that a shredder would remove all forensic evidence is not adopted as a verified conclusion.

### Suggested Evidence Labels

- **OpenStego Uninstallation Completed**
- **Downloaded Installer Removed**

## Task 3 — Examine Application Log Clearing

### Objective

Observe the effect of clearing one local event log and identify the evidence generated by that action.

### Lab Activity

The supplied procedure clears the **Application** log on PLABWIN10 and then examines the **System** log. The lab describes a System-log entry recording that the Application log was cleared.

### Interpretation

This is the central finding of the task: clearing one source of evidence can itself leave an observable record. The exercise affects the Application log, not every Windows log. The supplied instructions also note that forwarded copies may already exist on a separate collector.

Preserving an exported log supports evidence retention, but it does not by itself restore a cleared live log to its original state. No claim of complete restoration or undetectability is made here.

### Suggested Evidence Labels

- **Application Log Before the Lab Cleanup**
- **Application Log After Clearing**
- **System Event Recording Application Log Clearance**

## Task 4 — Remove Temporary Domain Admins Membership

### Objective

Reverse the direct group-membership change described in Exercise 2 and verify the resulting directory membership.

### Lab Activity

The supplied procedure removes Pablo from Domain Admins and then lists the group's members:

```powershell
net group "Domain Admins" pablo /delete /domain
net group "Domain Admins"
```

The stated result is that Pablo is no longer listed as a direct member.

### Interpretation

Removing direct membership reverses that specific change. It does not independently prove that the account has no remaining administrative access. Existing authenticated sessions and indirect group membership must be considered separately.

This matters here because the earlier BloodHound screenshot labels the Marketing Managers-to-Domain Admins relationship as `MemberOf`, while the written lab describes `GenericAll`. If nested membership exists, removing only Pablo's direct membership would not remove that indirect path. If excessive delegation remains, the escalation route could also remain available.

### Suggested Evidence Labels

- **Temporary Domain Admins Membership Removed**
- **Domain Admins Membership Rechecked**
